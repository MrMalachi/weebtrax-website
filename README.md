A music-mix archive and streaming site for an anime-focused DJ brand — 99 mixes and 44 scene clips, served from a FastAPI + PostgreSQL backend on Railway, with 8.3 GB of audio/video on Cloudflare R2 and the frontend on Cloudflare Pages.

## Architecture

```
Browser (React, no build step)
   │
   ├── weebtrax.com ─────────── Cloudflare Pages (static frontend)
   ├── api.weebtrax.com ─────── FastAPI + SQLModel on Railway ── PostgreSQL (Railway)
   └── media.weebtrax.com ───── Cloudflare R2 (8.3 GB: 99 mp3, 44 mp4, 44 jpg)
```

The frontend fetches mixes/scenes from the API (not from static JSON), the API is the only thing that talks to Postgres, and audio/video stream directly from R2 rather than through the API.

## Backend (`backend/`)

- **FastAPI** + **SQLModel** on **PostgreSQL**, deployed as a Docker container on **Railway**
- REST endpoints, all under `/api`:

  | Endpoint | Description |
  |---|---|
  | `GET /api/mixes` | All mixes with tracklists |
  | `GET /api/mixes/latest?limit=` | Most recently released mixes |
  | `GET /api/mixes/popular?limit=` | Most-viewed mixes |
  | `GET /api/mixes/{id}` / `/api/mixes/slug/{slug}` | Single mix + tracklist |
  | `PATCH /api/mixes/{id}/views` | Update a mix's view count |
  | `GET /api/scenes?page=&limit=&episode=&mood=` | Paginated, filterable scene clips |
  | `GET /api/scenes/{id}` | Single scene |
  | `GET /health` | Liveness check (Railway healthcheck) |

- Schema: `Mix` 1–N `Track` (tracklist entries), `Scene` — see `backend/models/`
- CORS is origin-locked to `weebtrax.com` via an `ALLOWED_ORIGINS` env var, not left wide open
- Media paths in the DB are bare object keys (`mixes/audio/foo.mp3`); the frontend prepends the right host for local dev vs. production so a CDN change is a one-line edit

## Notable engineering

- **Cross-origin audio bug**: after moving media to R2, audio played with a moving waveform and running timer but no sound. Root-caused to two independent causes (a CORS header gap and a stale service-worker cache) — fixing either alone still produced silence.
- **Data integrity catch**: 9 of 99 mixes had `audioPath`s generated by a different slugify rule than the canonical `slug` field, pointing at files that never existed. Found and fixed during the R2 migration, verified 99/99 against the real object list.
- **Deploy debugging**: a Nixpacks build reported "Deployment successful" while the container crash-looped on boot (missing `python`/`uv` on `PATH`) — only the runtime logs, not the dashboard status, showed the real failure. Fixed with an explicit Dockerfile.

## Local development

```bash
uv sync
uv run uvicorn backend.main:app --reload   # API on :8000
cd production && python3 serve.py          # frontend on :3000
```

Requires a local PostgreSQL instance (`DATABASE_URL` env var, defaults to `postgresql+psycopg://localhost:5432/weebtrax`). Seed with `python -m backend.init_db`.
